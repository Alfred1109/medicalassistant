# 康复方案链路核查（2026-11-07）

本次检查本地代码和隔离内存请求，不访问 113.44，不连接真实患者数据库，不调用 LLM，不启动或停止其他项目。结论是：康复方案存在身份授权、数据结构、临床语义和执行记录的共同断点，不能通过增加 TypeScript 字段或改一个 URL 宣称功能完成。本次不修改此链路业务代码，不迁移历史数据。

## 1. 已确认的断点

| 环节 | 本地证据 | 影响 |
|---|---|---|
| 路由授权 | `backend/app/api/routers/rehabilitation_router.py` 的方案、评估、运动路由均未依赖当前用户；`main.py` 挂载时没有补充用户依赖 | 方案列表可匿名调用；`patient_id` 查询参数不是患者归属检查。统一身份与对象授权必须进入全部读写链路 |
| 手工建方案 | `RehabPlanForm.tsx` 发送 `title/patientName/duration`；`RehabPlanCreate` 必填 `name/patient_id/start_date/goal` | 当前表单请求 422；不能用姓名或登录账号 ID 自动替代临床患者 ID |
| 手工编辑 | 表单继续发送上述字段；`RehabPlanUpdate` 不含这些字段，Pydantic 默认忽略额外字段 | 会发生部分修改被忽略、请求仍然成功；不能只把 TS 改成可选字段 |
| 响应字段 | 服务返回 `_id/patient_id/start_date/created_at/updated_at/body_part/duration_minutes`，前端类型及页面使用 `id/userId/startDate/createdAt/bodyPart/duration` 等不同组合 | 筛选、时间展示和 Redux 更新缺乏一致映射；多个无 `id` 的记录可能被当成同一记录 |
| 状态 | API 手工模型默认 `active`、说明含 `cancelled`；生成使用 `draft`；前端仅声明 `active/completed/archived` | 草稿、审核、签署、生效、终止的状态与权限没有统一实现 |
| 运动加入 | thunk 提交 `{exercises: [...]}`，接口读取 `{exercise_ids: [...]}` | 可能原样返回计划，界面误以为已经添加 |
| 运动身份 | 添加服务保存 `{exercise_id, schedule, progress}`；进度服务只按 `id` 或 `name` 匹配；页面期待完整 Exercise | 同一服务刚加入的运动不能按其 ID 记录进度；同名运动不能作为稳定身份 |
| 进度接口 | 前端 `PATCH /plans/{id}/exercises/{id}`；后端 `POST /plans/{id}/exercises/{id}/progress` | 当前请求 404；直接改成 POST 仍无法解决运动身份、授权及完成语义 |
| 进度语义 | 每次 `completed=true` 都增加总数；`false` 不撤回状态/计数；读改写整个运动与统计；以一次性运动总数计算坚持率 | 重试、撤回和并发会导致统计错误；必须区分“训练处方项”与“某次计划训练的执行事件” |
| 推荐 | thunk 一处 POST、一处 GET 使用 `patientId`；后端只提供 GET 并要求 `patient_id` | POST 405；另一请求 422；请求体亦缺患者主体 |
| 运动管理 | 前端有 GET/PUT/DELETE `/exercises/{id}` thunk；活动 router 未提供这些端点 | 调用无法完成；新增端点前须具备资源管理权限与版本策略 |
| 统计 | 路由调用 `calculate_plan_statistics/get_exercise_trends`，服务没有这两个方法 | 请求进入后会抛出属性错误；不能用固定数值或示例曲线代替 |
| 生成输入 | 页面提交患者年龄、病史等 `patientInfo`；router/service 仅向模型传入患者 ID、姓名、病情、目标四项 | 不能声称实际使用完整病史、生活方式或基因数据；更不能自动推导缺失的临床输入 |
| 生成失败 | 服务生成失败构造模拟或应急方案；数据库写入失败仍返回 `temp_...`；Agent 另有模型调用失败模拟响应 | 上游失败可能呈现为成功生成的临床草稿；应区分明确标注的隔离演示、真实生成失败与持久化成功 |
| 审核 | 页面发送 `{modifications: {...}}`，router 接收裸字典后原样交给 Agent；Agent 允许除 `_id` 外任意字段覆盖并把整个含 `_id` 文档放入 `$set` | 修改可能被嵌套为 `plan.modifications` 而未实际应用；缺少字段白名单、审核人、版本冲突和状态转换约束；含 `_id` 的更新行为须用真实 Mongo 验证 |
| 临床调整 | 代码根据三个反馈与硬编码阈值建议加减组数/次数；评估缺失疼痛默认满分，加权总分使用固定权重 | 现有代码不是已确认的肾病康复规则，也不是 113.44 的权威量表评分；不得用于新功能的正式验收 |

## 2. 历史数据范围

- 活动 `RehabilitationService`、Agent 审核及预测服务读写 `rehab_plans`。
- `RehabilitationPlan` 模型、通用 `RehabilitationPlanCRUD` 和 `mock_data_scripts/create_test_rehab_plans.py` 使用 `rehabilitation_plans`，用户档案也保存 `rehabilitation_plans` 引用。
- 仓库可证明两个集合名称及不同写入路径并存，不能证明真实数据库中哪一集合为空、哪一条记录权威，也不能据此删除、覆盖或双写。
- 本次容器清单未发现本项目运行中的 Mongo；没有连接 `.env` 中可能配置的其他数据库。历史实际记录、计数和冲突仍未核验。
- 迁移前应在明确授权的本项目数据副本中分别清点：集合数量、字段类型、ID、患者引用、中心/项目来源、状态、运动引用/快照、执行历史及两集合重复关系。姓名相同不作为合并依据。形成映射、冲突清单、可重放迁移及回滚验证后，才切换权威集合。

## 3. 隔离复现结果

使用项目 Python 3.12 虚拟环境、FastAPI router、真实 Pydantic schema、HTTPX ASGI transport；数据库服务依赖替换为只返回合成数据的 `AsyncMock`。另直接调用真实进度服务，仅替换其读取方法返回合成计划。没有外部网络请求或持久化写入。

| 请求 / 检查 | 结果 |
|---|---|
| 无 Authorization 的 GET `/api/rehabilitation/plans` | 200，返回合成其他患者方案；证明路由缺少认证门槛，不代表已读取真实患者数据 |
| 当前手工创建字段 POST `/plans` | 422，缺少 `name/patient_id/start_date/goal` |
| 当前前端进度 PATCH 路径 | 404 |
| 当前前端推荐 POST 路径 | 405 |
| `hasattr` 检查统计、趋势服务方法 | 两者均不存在 |
| 用添加服务产生的 `exercise_id` 结构调用进度服务 | 返回 `Exercise not found in plan` |

这些结果用于定位现状，不作为正式验收测试；后续测试应断言目标行为，不能把缺陷冻结成期望结果。

## 4. 完整修复的依赖顺序

1. 以已批准的统一身份架构为前提，完成操作者、临床患者、受试者、项目和中心映射；所有方案/评估/执行读写先校验患者归属和操作职责，默认拒绝无归属及跨中心访问。认证本身不能代替对象授权。
2. 在上述数据清点后，确定一个权威方案模型及存储路径。显式版本化 API DTO、存储文档与前端展示映射；拒绝未知写入字段。保留方案引用的 113.44 答卷修订、量表版本及输入快照。
3. 明确方案是四领域处方组合，运动只是其中一类。设计草稿、医护审核、签署发布、变更修订和终止，记录操作者、版本及审计；生成失败和保存失败返回可识别失败，避免临时 ID 冒充可审核记录。
4. 拆分运动库定义、方案处方项和训练执行事件。处方项独立稳定 ID，保留发布时快照；执行事件绑定处方版本、计划训练实例、操作者和事件 ID，并具备重试幂等、并发控制及更正历史。完成率/依从性分母以已确认的计划实例与时间窗为准。
5. 在前述契约确定后，一次性对齐列表、创建、编辑、审核、加入运动、反馈及统计 UI；明确推荐是读取既有建议还是有成本/持久化副作用的生成操作，再确定 HTTP 语义。
6. 补全权限拒绝、真实 Mongo 持久化、状态转换、并发/重试、时区/空数据及前端真实交互验收；不能仅用页面假数据或 thunk 测试宣布完成。
