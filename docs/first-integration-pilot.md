# 113.44 医护填报首轮隔离联调

状态：首轮隔离技术验证已完成（2026-11-07，全部合成数据，环境已清理）。端到端闭环「医护创建任务 → iframe 嵌入填报 → 提交 → 后端远端核实转待审阅」已在真实浏览器中打通；仅限隔离验证，未接通真实身份、真实患者或正式环境。患者本人账号仍尚未关联，不能用医护账号代替患者身份。

## 已核查的线上基线（2026-11-07）

- 113.44 肾病项目为项目 4「肾病康复综合评定项目」，现有项目数据不应被选作测试数据。当前未发现带明确测试标识的项目测试成员或受试者；需建立可隔离辨认的合成对象及明确授权，并保留来源和清理范围。
- 项目现有成员机制能够约束项目、中心及表单范围，但已有逻辑中空中心可能表示全中心或允许未分中心数据；新联调必须额外绑定非空中心与受试者并默认拒绝不匹配，测试成员不能获得全中心或管理权限。
- 两台服务器当前对外没有查到现成 HTTPS 站点，表单平台仍使用 HTTP；不能通过公网明文传输真实凭据或患者数据。正式接入须先有可信 HTTPS 与受控来源，合成数据的隔离技术验证可以使用受控本机回环和加密隧道，不代表正式环境已安全。
- 现有表单填报依赖登录用户和项目权限，但没有用于跨系统身份委托、固定资源的嵌入会话及可信状态回传的完整集成接口；不能以公开 URL、共享管理员会话或 Partner AI 密钥替代。

## 首轮交付与验收

1. 两端分别准备隔离实例和合成项目、中心、医护操作者、患者/受试者、表单、随访任务；对象之间的关联和授权显式创建，不根据姓名或邮箱自动匹配，不使用线上现有患者。
2. 两端通过经评审的标准身份与委托协议建立医护身份和受限会话。源端再次检查账号、项目、中心、受试者和表单权限，不能把研究成员身份直接视为临床授权。
3. 受限会话绑定操作者、患者/受试者、项目、非空中心、表单和版本、任务、允许的嵌入来源及有效期。嵌入只开放该会话所需入口，保留草稿恢复和版本锁；不放宽整个管理后台的 iframe 策略。
4. 提交后由后端向 113.44 查询确认答卷和状态；浏览器消息仅作为刷新提示，不能单独完成随访。记录真实操作者和代填关系，不把服务账号写成患者。
5. 验证错误患者/项目/中心、空中心、过期、撤权、重复请求、来源不匹配和伪造消息被拒绝；验证断网重试、草稿、最终提交及状态回传。只用合成数据，并在测试完成后按事先登记的隔离范围清理。

## 首轮隔离联调结果（2026-11-07）

两端均只使用带 PILOT 标识的合成对象与全新隔离库（113.44 使用 SM4 加密 SQLite 新库；medicalassistant 使用独立 Mongo 容器 `rehab-pilot-mongo` 的 `rehab_pilot` 库）。113.44 隔离实例以自签名 HTTPS（127.0.0.1:5503）运行，medicalassistant 后端 5504、前端 5501（本地 HTTPS，`/medical` 前缀代理等价生产 nginx 行为）。

已验证（含证据）：

- 端到端闭环：医护登录 → 创建填报任务（患者归属校验）→ 113.44 创建会话 → iframe 内一次性令牌换取委托会话 → 填写 3 题合成表单 → 提交（远端 response 生成）→ 成功页 postMessage 触发后端 `confirm` → 任务转 `confirmed`（待审阅），确认证据含远端 response_id、状态、提交时间与逐题答案，两端服务端读回一致。
- 跨站 iframe Cookie（AUTH03/EMB01）：委托会话 Cookie 仅在委托会话内改写为 `SameSite=None; Secure`（HTTPS 下），全局会话 Cookie 策略未变；真实 Chromium 浏览器内第三方上下文中委托会话建立与保持成功。
- frame 安全（EMB01）：`frame-ancestors` 仅按会话 `allowed_origin` 输出，`X-Frame-Options` 仅在委托会话内移除；管理后台端点在委托会话内仍被白名单拒绝（113.44 契约测试覆盖）。
- 一次性令牌与重放：embed 令牌用后即作废；实测第二次打开同一嵌入链接被拒（409），需重新创建任务。
- 默认拒绝（服务端，curl 实测 + 两端契约测试）：未认证 401；患者不存在 404；医生不在患者 `practitioners` 中 403 `PATIENT_NOT_ASSIGNED`；远端 scope 外项目 502（remote_code=scope_denied）；非 HTTPS `allowed_origin` 400（invalid_origin）；空中心受试者、无成员资格操作者、撤权受试者、伪造会话 Cookie、撤销客户端在 113.44 侧契约测试中全部被拒。
- 确认一致性核验：远端答卷的 project/subject/questionnaire/operator 引用与本地任务不一致时拒绝确认（`RESPONSE_MISMATCH`，契约测试覆盖）。
- 伪造 postMessage（真实浏览器实测）：错误 origin、错误 source、错误 type、结构缺失四类伪造消息全部被忽略，任务状态不变。postMessage 仅作为刷新提示，确认一律以后端向 113.44 查询的结果为准。
- 凭证卫生：集成客户端密钥仅哈希存储、明文仅创建时出现一次；embed 令牌本地只存哈希；测试后隔离环境已停止并清理（见下）。

联调中发现并修复的实现问题：

- medicalassistant 前端服务路径误拼 `/api/api/...`（契约测试直连后端未暴露，端到端联调暴露后修复）。
- 嵌入壳组件 postMessage 校验误用 `allowed_origin`（自身页面来源）比对 `event.origin`（发送方=表单平台来源）；已改为严格比对 embed_url 来源。
- 113.44 种子脚本在 SM4 加密启用环境下需先以 `rwc` 模式建立加密库文件，且空库检查必须发生在 `create_app` 自动建表之前；已修复。
- 为隔离联调新增 `FORM_PLATFORM_VERIFY_TLS`（默认开启校验；仅自签名证书联调置 False），未放宽生产默认。

本轮局限（如实记录）：

- 跨站 Cookie 的 SameSite 语义由浏览器执行，本轮以 Chromium 真实内核验证通过；未覆盖所有浏览器与其第三方 Cookie 收紧策略，正式环境必须使用可信 HTTPS 域名。
- 一次性令牌意味着嵌入页刷新/重开需要重新创建填报任务；草稿恢复依赖同一委托会话 Cookie 存续。嵌入式会话断开后的续填体验需要在正式接入前重新设计（例如以任务为单位重建会话）。
- 未覆盖断网重试、长草稿周期、并发撤权等时序场景；`IntegrationFillTask` 是试点隔离模型，随访领域模型收敛（FU01/FU02）时迁移。
- 测试数据清理范围已执行：删除 `/tmp/pilot-integration`（含 113.44 SM4 合成库、证书、脚本），`docker rm` 移除 `rehab-pilot-mongo` 容器（`rehab_pilot` 库随之销毁），停止两端隔离进程；两端主开发数据库未受影响（113.44 真实 instance 库全程未被本轮进程连接）。

## 正式环境前置条件

可信 HTTPS 域名、证书和回调地址；经确认的患者身份核验与账号关联流程；真实医护资质和中心权限；历史账户及公开演示密码处置；模型服务凭据轮换；两端数据库备份、回滚和授权撤销验证。这些条件尚未满足，不能以本地构建成功或 HTTP 可访问作为联通验收。
