# LLM 服务配置与历史凭据处置

`LLM_API_KEY` 没有代码内默认值，仅从部署环境或受控配置文件注入。配置使用 `SecretStr`，避免普通配置对象展示或 JSON 序列化输出原始密钥。实际 SDK 调用在统一配置边界取出凭据，不把它发送给浏览器。

运维应在受控密钥管理工具或服务环境文件中设置 `LLM_API_KEY`，文件只允许服务账户和管理员读取，不能提交到 GitHub。按厂商实际端点与模型设置 `LLM_API_BASE_URL`、`LLM_API_MODEL`；不要将密钥写进命令行参数、浏览器配置或验收截图。配置完成后按项目部署机制重启并验证。

未配置、空值或纯空白凭据时，相关 AI 请求返回 HTTP 503 和稳定错误码 `LLM_NOT_CONFIGURED`，提示联系管理员。基础及优化服务的普通查询、参数生成、方案生成、评估分析和流式启动都受该边界约束，不会因缺少配置返回缓存、模拟方案或“流已开始”，也不写入生成记录或方案。

这次改动只处理缺少配置及其错误传播。既有上游调用失败、临床生成和持久化失败的其他处理仍需按康复领域计划继续整改，不能由本项测试通过视为整体临床生成链验收。

仓库历史中曾包含硬编码凭据。从当前代码移除不会删除 Git 历史或使已泄露凭据自动失效。原凭据应在服务商侧撤销或轮换，检查其使用记录，再通过受控部署配置注入新凭据；不得复用历史值。历史重写和远端副本清理需要单独协调，不能以强推自动处理。
