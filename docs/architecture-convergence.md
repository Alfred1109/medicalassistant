# 康复系统架构收敛工作记录

本记录服务于跨业务模块的架构改造。当前采用模块化单体：一个前端、一个 FastAPI 应用和独立生命周期的 MongoDB；业务与外部系统按领域划分，不把新增服务部署作为架构优化的前提。此记录描述本地工作区，不能视为生产部署或临床验收。

## 共同边界

- 登录账号标识操作人，患者档案标识临床对象，113.44 受试者标识项目参与关系；必须通过可审计的明确关联连接，不按姓名、相同 ID 或研究角色推断诊疗权限。
- 113.44 管理统一身份及源问卷、答卷；康复系统管理自身患者授权、方案、随访和质控。两边通过受限接口交流，各自管理数据库。
- 发布、随访与质控的关键多文档变更使用真实事务；不支持事务时拒绝，未知提交结果必须可区分，不能顺序写入或假报成功。
- 改造沿现有业务入口推进，每次核对真实调用、历史数据、角色权限与事务一致性；现有未提交工作、生产库和已审核历史不自动迁移或删除。

## 工作范围和依赖

| 范围 | 当前事实与推进方向 |
|---|---|
| 患者、账号、权限 | 现有业务主要读取 `users` 患者；独立 `clinical_patients` 与账号关联已有基础，切换仍禁用。先收敛旧域读取入口，再逐域接入明确的临床患者和账号解析；须同时覆盖医护列表、本人、随访、健康档案、设备、方案、质控和统计，不能只切换单个读取函数。 |
| 随访及问卷 | 随访集中于 `FollowupService`；外部答卷、审阅和复评保留来源及历史。问卷身份、版本和启动已有本地实现，历史凭证清理、超时对账和完整撤权仍待闭合。 |
| 康复方案 | 结构、审核发布和患者反馈承担不同职责；先确定相同患者授权和事务边界，保留发布快照及历史，不以合并文件代替业务收敛。临床规则及签署责任须确认。 |
| 质控与报告 | 人工问题及过程监测应依赖同一患者范围和权威业务事实；正式 ICF、指标、报告与跨中心规则需临床和业务确认。 |
| 通信和通知 | 会话成员、账号状态和真实持久化是基础；消息幂等须由数据库唯一约束保证，异常时拒绝写入；多 worker 分发、连接中撤权及通知送达另行验证。 |
| 设备、临床工作台和 Agent | 按设备、报告、宣教、语音及模型能力划分职责，保留患者授权及来源追溯。真实设备、模型行为和临床适用性需独立验收；现有未启用路径不得未经兼容分析删除。 |
| 运行、审计与数据保护 | 启停通过根目录脚本，Mongo 独立管理。后台调度、全量备份恢复、迁移、告警与多进程边界需分别核实，不能把有限字段导出当成完整恢复备份。 |
| 多中心与隐私计算 | 为首期范围。真实中心、数据驻留、授权与科研任务未确认前保留明确依赖，不用模拟中心或一般传输加密宣称验收完成。 |

## 本轮执行与证据

本轮先处理共同事务边界、患者旧域读取和通信持久化的基础问题。各项实现、验证、失败与未完成的跨域迁移在此续记；历史快照与生产数据不在本轮自动切换。

- **事务：** 随访、康复发布和质控保留各自错误码与公开入口，共用 snapshot/majority 事务执行和未知提交状态；隔离副本集与 standalone 验证真实回滚和无事务时拒绝写入。
- **患者读取：** 当前 users-backed 患者读取、医护范围及姓名查询收敛至显式 legacy 存储适配器，随访和康复列表实际调用。临床患者域未切换，账号本人解析、发布/质控/提醒及跨域事务栅栏仍需逐项接入。
- **患者档案域分派：** 授权内核 `backend/app/core/patient_access.py` 的患者加载、对象访问、本人解析与医护范围查询按持久化 `patient_domain_state` 单例（`clinical-patients-v1`）分派 legacy/canonical：无状态文档保持既有 legacy 语义（含 503 歧义门闩）；`mode=canonical` 时对象加载走 `ClinicalPatientRepository`，本人解析必须经 verified `patient_account_links`（`repo.resolve_self`），不假设账号 ID 即患者 ID，canonical 范围查询自带 `status=active`；状态文档缺失、迁移中、未知版本或读取失败一律 fail-closed 返回 503（`PATIENT_DOMAIN_STATE_UNAVAILABLE`），不回退 legacy。canonical 模式当前未启用，无生产切换。
- **第一波段读取收敛：** 医护患者列表与医生统计、质控患者存在性/归属/范围读取、通信通知提醒收件人解析（会话成员与审计操作人保持账号身份）、表单集成的外部患者链接校验与任务范围、临床工作台本人解析与健康管理师/患者路由（标识歧义 503 不再降级 500）、康复发布授权患者校验、管理端患者列表（歧义分组 503 透传）收敛到共享 legacy 适配器，获得双字面兼容与歧义 fail-closed 防护；随访、设备、质控与康复列表的医护范围查询改走域感知 `assigned_scope_query`，legacy 下返回形状与原路径等价断言锁定。保留待第二波段：账号层读取与账号/患者同文档身份假设 33 处（盘点标注）、各域并发栅栏写、统计/报告/过程质控的患者集合聚合常量（已集中为模块常量，切换时各改一处）、`people_import` 写 `users` 与 `data_export`。
- **盘点工具与迁移演练：** 新增只读盘点工具 `backend/scripts/patient_reference_audit.py`：按集合统计患者引用缺失/双形态/悬空/歧义，判定口径与运行时适配器 identity_key 同构，分批游标处理大集合、缺省仅允许 localhost、写调用即失败断言。两次扩展覆盖第一代 `follow_ups` 缺 `patient_id` 的 `legacy_missing` 豁免口径（与 `followup_records` 两代并列对照）和 `patientmanager.daily_records`（点号集合名、`user_id` 双形态与 string `_id` 历史文档计数）。隔离真实副本集迁移演练 12+2 场景：正常迁移保留原 `_id` 并逐账号写 `legacy_same_document` 链接、同 key 歧义 fail-closed、幂等 noop、注入失败整体回滚、缺失字段显式缺省、standalone 拒绝；数据质量硬闸 4 类（`is_active` null、字符串时间、null 关系数组、非字符串 name）拦截坏数据；noop 重跑重算 legacy 基线指纹，漂移 fail-closed 报 `LEGACY_BASELINE_DRIFTED`，晚到患者只随结果上报 `latecomer_ids` 不自动补迁。`users` 全程只读；迁移提交后数据层不可逆，唯一回滚途径是完整备份恢复。
- **栅栏双载体基础：** 新增账号栅栏载体（独立 `account_fences` 集合）与患者实体栅栏字段双载体基础模块：同一事务内双载体 `$inc` 与 `matched_count` 复核、任一失败整体回滚，错误码归一与 upsert 重试语义有测试覆盖；纯新增未接线，现有 `users` 文档上的五类栅栏（访问/提醒/设备/填报/报告）保持不动，替换对照与计数不迁移原因记录在模块 docstring。
- **方案文档：** 新增[患者域第二波段切换方案草案](./patient-domain-cutover-plan.md)（五个前置门槛、七个波次、栅栏载体拆分方案与 `people_import` 决策点）、[历史患者数据迁移与核实方案](./patient-data-remediation-plan.md)（盘点/核实/归一/缺失处置/执行手册与 12 项决策清单）与[盘点工具说明](./patient-reference-audit.md)。均为草案，未经真实库验证，不构成切换或迁移验收。
- **通信：** 消息写入前要求目标库建立并确认幂等唯一索引，失败拒绝写入；历史读取不受阻，历史重复不自动删除。隔离 Mongo 验证并发首写去重、已有重复阻断和索引修复后恢复。仍须独立完成诊疗/中心授权、连接中撤权和真实多 worker 验收。
- **报告配置：** 报告调度 API 通过每请求数据库依赖创建服务，避免共享实例反复重绑数据库；没有启动旧后台调度或将其报告格式视为已验收。当前业务 JSON 导出仅移除部分凭据、仍含患者信息，字段和条数有限，不能用于完整数据库和媒体恢复；完整备份、恢复演练和多 worker 调度仍待单独处理。
- **患者与设备：** 用户确认设备绑定患者，由负责的医生或健康管理师管理；管理员可只读盘点历史非患者绑定，未自动删除或改绑。患者读取拒绝同字面 ObjectId/string 指向多个实体；设备、分析和维修服务共用请求数据库。绑定、解绑、配置和手工读数在事务内复核本地账号及患者范围，独立副本集验证了并发撤权和写入回滚。医护页面可选择已授权患者管理其设备，患者原有入口保留；真实设备采集未接入。本人解析仍只适用于旧域同文档关系，canonical 未切换。
- **临床报告：** 新增内容触发新修订及重新审核，审核快照与内容版本绑定；旧审核记录保留，但无版本化快照的历史报告须医护重新核实才进入新计算/方案来源。本地事务同时复核并锁定医患关系与账号状态；源端授权、OIDC 绑定的跨平台撤权尚不能由该本地事务保证。前后端需同批交付，报告写入要求 Mongo 副本集事务。
- **AI 调用：** Agent 主线与报告视觉识别保留原有模型/提示/失败语义，将同步 SDK 调用隔离到线程，避免阻塞事件循环；真实提供商、模型选择、参数及临床适用性仍需单独确定和验证。
- **业务数据导出：** 旧下载 API 仍可用，生成的 JSON 明确标识仅移除部分凭据、仍含患者信息、非数据库恢复备份，列出集合范围及实际截断。手动导出与定时导出时间分开记录；旧时间只作兼容参考。完整恢复备份和后台任务可靠领取仍未完成。

本轮后端全量回归 687 passed / 262 skipped；前端测试 102 passed、构建通过（有 chunk 体积警告）。隔离 Mongo 专项分别验证通信唯一索引、事务回滚、报告版本与并发撤权、设备患者归属及并发撤权。上述为本地代码与合成数据结果，尚不等于所有业务域完成重构、生产部署或临床验收。

患者档案批次后复跑基线：后端全量回归 `DEBUG=false` **767 passed / 277 skipped**（跳过含副本集门控条件用例）；前端测试 102 passed、构建通过（chunk 体积警告）不变。边界与开放项：canonical 域仍未启用（无生产切换，迁移 CLI cutover 保持禁用）、legacy 503 歧义门闩仍在、迁移未在真实库执行（仅在隔离副本集演练）；历史数据核实处置 12 项决策、第二波段 `people_import` 决策点与晚到患者处置流程等开放清单见上述三份方案文档。
