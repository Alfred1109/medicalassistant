# 外部验证清单（119.45 正式环境）

日期：2026-11-15。本清单列出患者档案架构与系统上线的收尾验证项中，**无法在本地完成、需要 119.45 环境访问或业务拍板**的部分。每项注明：目的、需要什么、执行方式、验收标准、风险。配套文档：`deploy-ops-checklist.md`（部署检查单）、`patient-data-remediation-plan.md`（数据迁移方案）、`patient-domain-cutover-plan.md`（切换波次）。

**凭据安全约定：不要在对话里粘贴生产密码。** 建议方式：建临时只读账号 + SSH 隧道，用完即轮换；或由运维在服务器上代跑我给出的命令、把输出文件传回。

## A. 数据盘点与患者域切换（对应清单第 1、2 项）

### A1. 生产库只读盘点（G1 门槛，切换前置）
- **目的**：真实历史数据跑患者引用盘点（歧义/悬空/双形态/缺失）与标签唯一性盘点，产出 G1 门槛判定。本地无真实库，此前盘点无证据效力。
- **需要**：Mongo 只读账号（`read` 角色即可）、目标库名、Mongo 版本与端口、是否需要 SSH 隧道。
- **执行**（我给命令，运维代跑或开隧道我来跑均可）：
  ```
  backend/scripts/patient_reference_audit.py \
    --uri "mongodb://只读用户@119.45.x.x:27017/库名?authSource=admin" --allow-remote
  backend/scripts/label_uniqueness_audit.py --uri "…" --allow-remote
  ```
  只读断言：脚本内无任何写操作（已由单测锁定）。
- **验收**：歧义组=0、悬空=0（或逐条书面结论）、标签重复=0；不达标项进入核实流程（remediation-plan §3，需要业务侧输入的 4 个问题在那时提出）。
- **风险**：无（纯只读）。大集合预计分钟级，建议业务低峰跑。

### A2. 生产数据克隆迁移演练（波次执行前必做）
- **目的**：拿真实数据形态在隔离环境完整演练 `migrate_legacy_patients` + canonical 全链路，确认迁移产物、漂移校验、晚到者行为在真实数据上成立。
- **需要**：一份生产库 mongodump 归档（A1 之后由 backup 工具产出即可），传输给我或在服务器隔离实例上演练。
- **验收**：演练 14+ 场景在真实数据上通过；报告所有数据质量硬闸命中项（`is_active: null`、字符串时间、null 关系数组、name 类型不符——迁移会整体拒绝，需先清洗）。
- **风险**：零（不触碰生产）。

### A3. 切换执行（波次 1–6，需维护窗口）
- **前置**：A1 达标 + A2 报告确认 + D 组业务决策全部拍板 + A4 备份完成。
- **需要**：维护窗口（预估停机时长取决于数据量，演练实测给出）、执行授权。
- **执行**：按 cutover-plan 波次逐波推进，每波验证清单+回滚方式（显式改 mode，禁止删状态文档）。
- **风险**：迁移提交后数据层不可逆——唯一回滚是 A4 的完整备份恢复；这就是为什么 A2 必须先行。

### A4. 生产备份链路落地
- **需要**：119.45 服务器 cron/systemd 权限（或运维代配）；服务器上 mongodump 可用（版本与 Mongo 匹配）。
- **执行**：按 deploy-ops-checklist「日常运行」节配置 backup_mongodb.py 定时任务 + verify_restore 定期对账；归档加密存放。
- **验收**：一次真实「备份→隔离恢复→对账」闭环在 119.45 完成（本地已演练，命令照抄检查单）。

## B. 部署与正式 HTTPS/浏览器验收

### B1. 两端新版本部署
- **需要**：119.45 的部署方式说明（git 拉取 / docker / 手工包）、当前运行版本、回滚方式。
- **内容**：康复端 backend + frontend（本轮 47+ 提交）、源端（5 个提交：委托/版本/代际/限流/幂等/维护脚本）。
- **注意**：源端有 schema 变更（幂等表+部分唯一索引，启动时自动补齐，存量重复活跃行只告警不阻断）与 `.env` 新键（`INTEGRATION_RATE_LIMIT_*` 可选，有默认值）；`TRUSTED_PROXY_HOPS` 必须配置（反代后缺省 0 会拒绝 create/launch）。

### B2. 正式 HTTPS 全链路验收
- **需要**：正式 TLS 证书配置确认、OIDC provider 生产启用（签名密钥文件、`OIDC_CLIENTS_FILE` 含两端配对）、一个验收窗口。
- **验收**：本地预演（docs/local-https-rehearsal.md，T47 产出）照抄执行：真实登录 → 创建填报任务 → 嵌入填报 → 草稿 → 恢复 → 提交 → 审阅 → 方案发布 → 反馈 → 撤权即时生效。
- **风险**：SameSite=None Cookie 仅在 HTTPS+Secure 下工作——纯 HTTP 环境此链路必然失败，不是缺陷。
