## 已发现的SDK和实际边界

归档含 Android BLE 原生 AAR（`vpprotocol-2.3.68.15.aar`、`vpbluetooth-1.20.aar`）、示例与接口文档，以及 iOS `VeepooBleSDK.framework` 和示例。未发现供浏览器/Python直接使用的 SDK 或设备云 REST API；这些是包内文件盘点结果，不排除厂商另有未提供接口。

Android 文档中的设备连接流程要求 notify 建立后先 `confirmDevicePwd`，再 `syncPersonInfo`；设备命令应串行，具体功能由设备能力回调、型号及固件决定。Demo使用 Java/Kotlin 17、minSdk 24、compileSdk 34、targetSdk 35，仅是其编译配置，不代表已验证用户手机兼容性。

针对 JMD-540，归档文件名和 1,529 个文本文件未找到明确型号映射、专用密码或能力配置；未检查二进制内部映射，因此不能据此判断 SDK 是否支持该型号。Demo 的 `0000` 是通用示例密码，不能视为该设备的密码；Demo 中固定的身高、体重和年龄也不能用于实际患者。需要实机记录扫描名称、设备与固件信息、密码验证和能力回调，并向厂商确认。

说明文档列出部分疾病风险、心脏预警及部分 HRV、呼吸率和 ECG 等能力需要另行商务授权；接口存在不代表手头设备支持、指标准确或已获授权。具体以设备厂商书面确认及实际测试为准。

## 项目现状与风险

- [设备适配器](../backend/app/services/device_adapters.py) 目前有随机模拟指标，并存在字符串标识作为对象访问的类型问题；不能作为真实生理数据接入。
- [设备路由](../backend/app/api/routers/device_router.py) 与当前认证返回对象存在类型不一致；设备同步需完善患者归属、医护授权和中心范围检查。
- 现有绑定记录没有完成原生蓝牙持有验证，不能把数据库状态或 `last_connected` 当成已经与真实设备建立连接。
- 原生设备指标、采样时间、单位、设备标识和固件版本还没有经过端到端匹配；演示数据与临床数据边界需要明确。

## 拟议数据链及验收前提

设备 → 用户授权的手机原生 BLE 采集端 → 受限设备接入 API → medicalassistant 设备/患者绑定与观察值 → 由医护确认的规则或后续分析。

已确定目标设备型号和 Android 平台，还需确认设备固件、每项授权指标、原厂技术支持、患者绑定方式、机构与网络环境；不能把 BLE SDK 视为5G联网能力本身。设计应覆盖原生连接状态机、能力协商、采集主体和患者核实、换绑历史、原始时间与时区、数据单位、质量/来源、离线缓存、幂等上传、乱序和重传、撤权与审计。

正式验收需要真实设备和授权账号，逐项检查绑定、重连、重复上传、换绑、跨中心拒绝、时间偏差和与设备原始读数的一致性。该评估不是设备有效性、医学准确性或合规性结论；当前未进行真实设备接入。
