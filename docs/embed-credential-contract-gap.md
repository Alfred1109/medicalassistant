# 嵌入填报凭证与恢复链路待补契约

日期：2026-11-08。本文记录本地代码核查和实现依赖，不代表已部署能力。

## 已修复的消息边界

`FormFillEmbedPage` 通过 iframe ref 获取实际 `contentWindow`，只接受该窗口发出的消息，并继续校验表单平台 origin、消息结构和非空会话标识。来自同源兄弟窗口、弹窗或其他父窗口的复制消息不能触发确认。确认仍由后端查询远端答卷状态完成。

验证：`node --test tests/form-fill-message.test.cjs` 的两项安全正反例通过；前端严格构建通过。当前证据为函数测试和构建，不替代真实浏览器跨站部署验收。

## 凭证持久化缺口

源端 `app/routes/integration.py` 创建会话时返回 `/integration/embed/<token>`。本地 `integrations/forms/models.py` 将完整 `embed_url` 同时保存在 `session` 和 `fill_sessions`；`GET /fill-tasks/{task_id}/embed-url` 再次返回该 URL。因此即使单独的 token 字段只存哈希，一次性凭证仍能从持久化 URL 中恢复，现有“明文不落库”注释并不准确。

不能只删除写入的 URL：目前任务列表按 task ID 打开嵌入页面，页面稍后向后端获取 URL；哈希无法还原启动凭证。需要双端契约同时调整，保留同一远端会话和同一草稿，而非通过新建任务掩盖恢复问题。

现有源端一次性入口还是先查询状态再写 `embedded`，消费操作未使用原子条件变更；并发请求可能同时通过 `created` 检查。未来启动契约须同时保证消费原子性。

## 实现前置

已确认要求是：项目或中心权限撤销、成员或账号停用后，即使后来恢复授权，旧链接和旧委托仍永久失效。源端当前 `FillSession` 仅保存主体和资源 ID，没有记录可覆盖全部授权变更的代际。仅在每次访问时检查“当前有权限”，不能发现撤权后恢复的历史，不能满足上述要求。

应先覆盖账号、项目成员、中心、客户端和资源授权的全部变更入口，建立单调授权版本或不可逆会话失效记录。会话绑定创建时的授权上下文，变更后旧会话不可恢复。ORM 事件或单个路由钩子若不能覆盖批量写、删除和重建路径，不能作为完整保证。

本地代码盘点显示写入分散于 `ProjectService` 的成员、中心和项目状态操作，`admin` 的账号修改/删除，表单关闭、版本及授权操作，客户端/Grant 变更，以及患者和受试者生命周期操作。成员重新启用可能清空 `revoked_at`，项目强制删除包含批量更新；因此不能把当前状态或单个 ORM hook 当作完整历史。还须逐项验证维护脚本和全部写者后才能声明覆盖完整。授权版本变化应和对应业务变更同事务提交，并保留已提交答卷及不可逆失效证据；普通资料变更不应无差别使全部委托失效。

## 双端启动与恢复方向

具备上述失效机制后，再实现以下契约并进行隔离端到端验证：

1. 本地只保存会话引用、非敏感来源及状态，不保存含凭证的 URL。创建或启动响应中的短期凭证只在内存中透传，响应禁止缓存。
2. 启动使用受控 POST，由源端核实客户端、真实操作者委托、当前资源权限以及会话授权代际。未消费的启动凭证可原子轮换哈希，旧凭证立即失效；消费也采用原子 `created → embedded` 条件。
3. 已嵌入的会话通过无凭证恢复入口继续同一草稿。恢复入口必须依赖源端有效的受限 Cookie，核对同一会话、操作者及授权上下文；不能仅凭 session UUID 自动登录。Cookie 丢失时，按明确的重新认证委托流程恢复，不能回退为长期可复用链接。
4. 历史 `session.embed_url` 和 `fill_sessions[].embed_url` 需要独立、默认 dry-run 的盘点和脱敏迁移；本轮未访问或修改现有业务库。

必要验收包括：全落库文档不含实际 token；旧 URL 不再返回；同源其他窗口拒绝；并发双消费只有一次成功；已有 Cookie 的同会话草稿恢复；无 Cookie 拒绝；撤权后恢复权限也不能复活旧会话；未知提交和远端失败不误报成功。测试中 URL 必须使用与 `embed_token` 相同的合成 token，避免字段分别断言漏掉 URL 泄漏。

本轮仅完成消息窗口来源修复，未开放新的启动或恢复接口，也未改动源端或业务数据库。
