# 医疗时间线的实时事实与历史视图

`GET /health-records/timeline/{patient_id}` 保留原患者授权、日期与类型过滤和分页，
默认 `view=current`。健康档案、随访、健康数据、康复评估、ICF 评估按事实集合
实时投影，Mongo `$unionWith` 合并后统一过滤、稳定排序和分页，不先全量读入进程。
健康档案统计中的最近活动共用同一读取入口。

来源时间采用既有语义：健康记录优先 `updated_at`、回退 `created_at`；随访优先
`actual_date`、回退 `scheduled_date`；健康数据取 `recorded_at`；康复评估取
`created_at`；ICF 评估取 `assessed_at`、回退 `created_at`。原始来源日期保留在
`data.original_timestamp`。没有合法日期的条目返回 `timestamp=null`，排在末尾，
不猜测当前时间；有日期过滤时不混入未知日期。无时区查询按既有存储的 UTC 语义，
带时区查询转换 UTC；结束时间包含边界，反向窗口返回 422。

`view=history` 只读原 `medical_timelines` 快照，保留未知历史类型、重复快照及
已软删来源的原快照，不代表当前事实。两个视图执行同一授权检查。患者页面先请求
`GET /health-records/patient-context`，服务端经 verified 账号链接解析本人患者实体，
后续每个读取请求仍重新授权，不假定账号 ID 等于临床患者 ID。

当前视图的历史关联规则是来源类型加 `related_ids[0]`，严格限定同一个患者：

- 唯一事实源存在时，不再重复展示旧副本；源已软删时也不复活其旧副本。
- 没有可核实来源时，保留并标记 `data.source.orphan=true`。
- 同字面值的 ObjectId/字符串 `_id` 双命中时，不猜测来源：两份当前事实保留，
  历史快照保留并标记 `data.source.ambiguous=true`。响应 ID 包含集合、Mongo ID
  类型和字面值，避免 React 键冲突和同时间分页顺序不稳定。
- 不按标题、读数、时间相似度合并记录，也不改写历史集合。

健康记录、健康数据、随访的新写入和更新停止维护 `medical_timelines` 副本。
随访节点的并发版本、事务、审计及复评链继续独立生效。设备来源、原始读数、
单位与质量标志进入时间线 `data.metadata`，页面显式展示质量待核实信息；化验
名称/结果和复合血压全部保留，不将有质量问题的数据包装成正常临床结果。

查询索引沿启动期统一管理：只对已经存在的六个来源集合补普通非唯一
`patient_id` 索引，已有完整同前缀索引时复用，不隐式建集合、不变更唯一性。
历史源关联用本地 ID 候选与原生 `_id` 索引匹配；真实 Mongo explain 测试断言
五类关联使用 `_id_` 且无 collection scan。部署后的应用启动会尝试建立缺少的
普通索引，失败会记日志并保留读取；本轮只在隔离测试库执行，没有修改生产库。
启动时不存在的集合首次创建后，可在下一次启动或维护期调用索引管理入口补建。
